# 拆解：LotGo 这类「版式抽卡机」是怎么做的

只看截图能推出来的结论，以及本仓库对应的复刻实现。

---

## 一、先定性：它不是 AI 生图，是参数化排版引擎

三条证据：

1. **面板上有 `←` `→`。** 能精确回到上一张，意味着一张图可以被完整重放。生成式图像做不到这件事（同 prompt 不同噪声就不一样），但「种子 + 纯函数」可以——只要存住 seed，随时能把同一张原样算回来。
2. **海报上自己印着 `NEW PAGE EACH CLICK`。** 点一次 = 抽一次 = 换一个 seed。
3. **整个右侧面板全是确定性参数**（对比度、网格强度、标题组数量、散文诗大小）。这是排版引擎的入参表，不是模型的 prompt。

所以核心结构就一句话：

```
(参数对象 P, 随机种子 seed) ──纯函数──> 元素列表 ──> DOM/SVG
```

`P` 来自面板，`seed` 来自点击。历史记录只要存 seed 数组，前进后退就是零成本的。
本仓库对应：`src/engine.js` 的 `compose(P, seed)` + `render()`，`src/ui.js` 的 `state.history`。

---

## 二、最关键的一处设计：字号是反解出来的，不是填出来的

截图里「标题整体大小」显示 **`0px`**，旁边还有个「**固化大小**」按钮。这两处合起来暴露了机制：

- 字号本来是**算**出来的，所以滑杆显示的是相对偏移量（0 = 不偏），不是绝对值；
- 「固化大小」= 锁死，不再跟着栏宽自适应。

算法就是一行：

```
字号 = 栏宽 ÷ (这行字的总宽度(em) + 字距 × 字数)
```

这是整套东西「看上去像设计师排的」的唯一秘密。随机生成的版面之所以通常很丑，是因为字号和栏宽没关系；一旦让标题**正好撑满版心**，随便抽都成立。截图里的 `VOID`、`SERENDIPITY`、`ECHO` 全都严丝合缝顶到版心两边，就是这么来的。

本仓库：`fitFontSize()`。一开始我用平均字宽估算（拉丁 0.62em / 汉字 1.0em），大写衬线体会算窄、冲出版心；改成用 `canvas.measureText` 真实量一遍就准了。注意 CSS 的 `letter-spacing` 是**每个字后面都加一份**（含最后一个），所以分母是 `n` 份不是 `n-1` 份。

## 三、「风格N」是用户存的快照，不是设计师风格库

预设区里混着这些名字：

> 保存测试、多选测试、分层测试、风格6、风格7、风格16、风格20、风格21、风格26、风格35、风格37、风格40、风格41

两个细节：

- **「保存测试 / 多选测试 / 分层测试」是调试时留下的。** 一个交付给用户的风格库不会叫这个名。
- **编号不连续**（缺 1–5、8–15 一堆）。说明能删能改，存在 localStorage 里。

所以「风格N」= **把当前整个面板状态打一个包存起来**。作者调出一个好看的组合，点保存，就多一个格子。旁边那些有正经名字的（新中式、理性宋骨、日式书卷、港式杂志、庄重石刻、等宽技术……）是同一个机制下手工命名的成品。

**多选**也能从截图读出来：一批预设带**白色描边**（理性宋骨、诗两行、极细高级、极简轻黑、当代品牌…），只有「风格37」是**绿色实心**。合理解释是：描边 = 进了混抽池，实心 = 这一抽命中的那个。所以抽卡时先在选中的预设里随机挑一个，再用它的参数生成。

本仓库：`BUILTIN` + `localStorage['lotgo.presets']`，单击套用 / Shift 多选，`draw()` 里用 seed 决定命中哪个。

## 四、图层开关 = 渲染管线的分层

两排绿色按钮：

```
底色  分区  线条  杂   图片  纹理
文本  装饰  图形  窄缝  边栏  通栏
```

每个就是管线里一个独立的生成函数，绿色=开。这样拆的好处是调试和出效果都快：想要极简就只留「底色+文本+线条」，想要满版就全打开。

复选框那一排是**模式**，改的是生成规则而不是开关：

| 模式 | 推测作用 | 本仓库实现 |
|---|---|---|
| 实验模式 | 放宽约束（页边距、元素数量可以更野） | 边距随机区间放大、图形数量上限提高 |
| 撞色分区 | 分区块用高饱和对比色，不是低透明度叠色 | `modes.clash` 切换色板与不透明度 |
| 随机切割 | 提高递归切割深度 | guillotine 深度 1–2 → 2–4 |
| 卡片模式 | 整体收成卡片（加白边/圆角） | 未实现 |
| 原图模式 | 图片不分块、不上蒙版 | `modes.rawImage` |
| AI分层 | 抠图分前后景，让文字压在主体后面 | 未实现（要模型，见第七节） |
| 手写蒙版 | 手绘感不规则裁切边 | 用抖动多边形 `clip-path` 近似 |
| 通栏蒙版 | 通栏色带用墨色压图 | `modes.bandMask` |

## 五、「网格与结构」= 三种布局求解器

`正交 / 非正交 / 数学曲线` 是三套排布方式：

- **正交**：规规矩矩的栅格，元素对齐到网格线；
- **非正交**：整组旋转/错切几度；
- **数学曲线**：标题**逐字**沿参数曲线定位，每个字再按该点切线角度旋转。截图里那种沿弧线走的标题就是这个。

上面的「强度 1.0」影响网格的约束力度——强度高=贴得紧、边距小，强度低=松散。

本仓库：`ARCHETYPES`（5 个版式母题：压顶、中轴、侧栏、底锚、角部）+ `grid.mode` 三种模式 + `guillotine()` 递归切割。

另外随机版面必须有**避让**，否则文字会糊成一团。做法很朴素：记录已占区域，新元素随机试 ~28 个位置，取不打架的那个（`tryPlace()`）。我第一版没做，散文诗直接压在大标题上；加完立刻就能看了。

## 六、「标题组 / 散文诗」= 内容模型 + 文案池

面板上是：大标题组 1、小标题组 2、小标题相对大小 27%、散文诗数量 2、散文诗大小 25%、刻度字。

说明内容不是自由输入，而是**有类型的槽位**：大标题 / 小标题 / 散文诗 / 刻度字（就是那些边角上的小号等宽字，`FIG. 4`、`PROOF`、`LAYOUT SPEAKS`）。每个槽位从文案池里抽。所以每张图的字都不一样但都"像那么回事"。

「对齐：左右 / 居中 / 阵列 / 随机」是这些槽位的对齐策略，**阵列**大概是两端对齐（justify）撑满。

---

## 七、画面调色和纹理：一条 CSS filter 解决

- 对比度 / 饱和 / 明暗 → `filter: contrast() saturate() brightness()`，加在最外层容器上，旁边的「生效」勾掉就是 `filter:none`。零成本、实时。
- 纹理 `W-0 / W-1 / W-2` + 强度 → 一张噪声图叠在最上层，`mix-blend-mode: overlay`，强度就是 opacity。噪声用 SVG `feTurbulence` 现生成，不同 `baseFrequency` 就是 W-0/W-1/W-2 这几档（粗颗粒/细颗粒/纸纹）。「设为默认」= 存到 localStorage。

---

## 八、所以「vibe coding」在这里具体指什么

这套东西的形态非常像**单页 HTML + 一个巨大的参数对象**，跟模型一轮轮加出来的：

1. 先有个能画方块和字的画板；
2. 「给我加个纹理」→ 多一个图层开关；
3. 「标题老是跑出去」→ 加字号反解；
4. 「字压一起了」→ 加避让；
5. 「这套参数好看，存下来」→ 多一个「风格N」；
6. 版本号 `v1.10` + 预设里残留的「保存测试/分层测试」= 一直在迭代、没清理。

它不需要后端、不需要模型推理，所以能做到点一下瞬间出图。唯一可能真用到模型的是「**AI分层**」（把上传的照片抠成前景/背景，好让文字穿插在主体之间）——这是整个面板里唯一一个纯前端算不了的功能。

顺带说，第一张截图角上那条 `Approval required：你可以看一下下载里面的 film 那里有照片` 也侧面印证了工作方式：作者是让 agent 直接读本地照片目录接进这个工具的。

## 九、本仓库复刻了什么 / 没复刻什么

| | 状态 |
|---|---|
| 种子随机 + 前后翻页精确复现 | ✅ |
| 字号反解撑满版心（canvas 真实测量） | ✅ |
| 5 种版式母题 + 正交/非正交/数学曲线 | ✅ |
| 递归切割分区 / 撞色 | ✅ |
| 12 个图层开关 | ✅ |
| 图片分块、手写蒙版、程序化占位图、上传本地图 | ✅ |
| 画面调色 + feTurbulence 纹理 | ✅ |
| 预设快照（内置 12 套 + localStorage 自存 + Shift 多选混抽） | ✅ |
| 中英文案池 / 标题组 / 散文诗 / 刻度字 | ✅ |
| AI 分层抠图 | ❌ 需要模型 |
| 卡片模式、导出 PNG | ❌ 未做 |
| 真正的字体库（现在只用系统字体栈） | ❌ 有版权成本 |

差距最大的是**字体**。原作那种质感有一半来自字体选得好（细宋、老报纸体、等宽），而字体是要授权的。系统字体栈能跑通机制，但出不来那个味道。
