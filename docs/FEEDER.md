## 2. 文件结构（`feeder.html`，约 920 行）

按出现顺序：

| 区块 | 内容 |
|---|---|
| `<style>` 左栏 | `html{font-size:clamp(11px,min(2.2222vh,1.4625vw),22px)}`：**1rem = 视频 720 高画面里的 16px**，所以左栏所有尺寸直接用「视频像素 / 16」写 rem |
| `<style>` 机器 | `#rig` 575×720 的设计坐标盒子，整体 `scale`；`#paper` 纸带窗口；`.blur` / `.fog` / `.edge` 是纸出口的雾和两侧阴影 |
| `<style>` 窄屏 | `body.narrow`（< 720px 宽）改成上文下机 |
| `<style>` 样稿 | `.s-neon` `.s-orb` `.s-prism` `.s-retro` `.s-col` `.s-silk` `.s-grid`：纸上 7 张网页 |
| 隐藏 `<svg>` | 样稿共用滤镜 `#fxNeon` `#fxBrain`（多份拷贝都引用这一份） |
| `<main id="copy">` | 左栏：头像、标题、正文、两个按钮、合作方区 `#logos` |
| `<div id="rig">` | 机器，三层：**后层 svg（线缆）→ `#paper`（HTML 纸带）→ 前层 `svg#front`（机身）** |
| `<script>` | 见下 |

脚本里的主要标识符：

| 名字 | 作用 |
|---|---|
| `BASE_SPEED = 19` / `HOVER_SPEED = 5` | 走纸速度（设计坐标 px/s）；鼠标停在纸上时放慢 |
| `LOGO_PERIOD = 4000` | logo 轮换周期 |
| `REDUCE` | `prefers-reduced-motion`：不自动走纸，logo 直接切换不虚化 |
| `rtri()` / `silk()` | 霓虹圆角三角形、丝绸波浪线的生成函数（样稿用） |
| `CARDS` | 纸上 7 张样稿：`{ h: 站点高度(1280 宽下), html }`，渲染时缩放 0.2 → 256px 宽 |
| `G` / `LOGOS` | logo 小图标 + 4 组 × 4 个虚构品牌字标 |
| `ensureCopies()` | 纸带按需叠几份同样的一套，保证够长 |
| `layout()` | 算机器缩放和位置；纸窗口高度拉到视口底；窄屏时给电路板挂渐隐遮罩 |
| `parts()` | 用 JS 生成芯片焊点 `#pins`、母座 `#hdr`、轴承刻线 `#knurl` |
| `drawKnurl()` | 轴承表面刻线随走纸转（圆柱投影 `y = cy − r·cos θ`，只画朝前半圈） |
| `frame()` | 每帧：速度向目标速度指数回落、累加位移、平移纸带、转轴承、指示灯亮度 |
| 事件 | `wheel` 快进/倒带；`pointer*` 拖纸；`keydown` ↑↓/空格推一把 |
| `swapLogos()` | logo 依次加 `.off`（blur 7px + 透明）→ 换内容 → 依次去掉 `.off` |

### 关键算法

- **纸带循环**：一套高 `setH`，叠 `copies = 1 + ceil(paperH / setH)` 份；
  `translateY = mod(off, setH) − setH`。内容往下走，新内容从上面露出来，接缝不跳。
- **速度**：`v += (base − v)·(1 − e^(−2.4·dt))`；滚轮 `v += deltaY·2.6`，夹在 ±2400；
  拖拽 1:1 跟手，松手时把拖拽速度交给 `v` 做惯性。
- **布局**：桌面 `scale = min(H/720, W·0.56/575)`，机器在右半屏居中、不出右边界；
  窄屏 `scale = min(W·1.02/575, max(0.42, (H − 文字底)/600))`，纸中心对齐屏幕中线。

## 5. 怎么验证

改完至少确认这几件事（之前每次改都这样回归过）：

1. 1094×720 截图和参考帧并排看构图
2. 走纸空闲速度 ≈19（设计坐标 px/s）；悬停 ≈5；滚轮能正反走；拖 100px 纸动 100px
3. logo 轮换是「依次虚 → 空 → 依次显」
4. 1920×1080、1000×1000、390×844（手机）三个尺寸不重叠不穿帮
5. 控制台无报错

本地用 Playwright 的话（需要先装 `playwright` 和 Chromium），测速度的核心就这几行：

```js
const { chromium } = require('playwright');
(async () => {
  const b = await chromium.launch();
  const p = await b.newPage({ viewport: { width: 1094, height: 720 } });
  await p.goto('file://' + require('path').resolve('feeder.html'));
  const ty = () => p.evaluate(() =>
    parseFloat(getComputedStyle(document.querySelector('#strip')).transform.split(',')[5]));
  await p.waitForTimeout(500);
  const a = await ty(); await p.waitForTimeout(2000); const c = await ty();
  console.log('idle px/s:', ((c - a) / 2).toFixed(1));   // 期望 ≈19（遇到取模回绕时重跑一次）
  await p.screenshot({ path: 'feeder-1094.png' });
  await b.close();
})();
```

对照参考时，用 ffmpeg 从视频抽帧、裁局部放大最有用：

```bash
ffmpeg -ss 3 -i 参考视频.mp4 -frames:v 1 frame.png
```

```bash
ffmpeg -i frame.png -vf "crop=500:500:560:0,scale=1000:-1:flags=lanczos" ref-machine.png
```

没有 ffmpeg 的话，Python 的 OpenCV（`cv2`）也能抽帧、量亮度。纸出口雾的透明度就是这样量的——
每行取全片几十帧的亮度，**标准差小 = 雾挡住了内容，标准差大 = 内容透出来了**：

```python
import cv2, numpy as np
cap = cv2.VideoCapture('参考视频.mp4'); rows = []
for i in range(0, int(cap.get(cv2.CAP_PROP_FRAME_COUNT)), 15):
    cap.set(cv2.CAP_PROP_POS_FRAMES, i); ok, f = cap.read()
    rows.append(cv2.cvtColor(f, cv2.COLOR_BGR2GRAY)[120:300, 740:945].mean(axis=1))
A = np.array(rows)   # 每行：np.median(A[:, k]) 是雾色附近的亮度，A[:, k].std() / 透出处的 std = 透出比例
```

页面这边用同样的统计：Playwright 里把 `off` 拨到 40 个不同位置各截一张（`v = 0; off = setH * i / 40`），
取同样的行列。改材质时也一样，在参考帧上逐列取亮度（视频坐标，如电机 x=650、辊子 x=842、轴承 x=653），
对着把渐变的 stop 标出来。

## 6. 还差什么 / 下一步

已做（第三次提交）：

- **材质标定**：辊子、轴承、电机罐的渐变按参考帧逐列亮度重标。之前最大的差距是「不够圆」：
  参考的高光带很亮、下半截压得很暗，旧版的渐变太平。顺手更正了轴承「中间深色」的误读，
  右侧架做了背光，电机上的刻印压深一档（罐身下半截变暗以后旧的刻印颜色会糊）。
- **纸出口雾**：按量出来的透明度曲线重做（第 1 节），由 112px 延长到 172px。改后实测：
  y204 透出 0.39（参考 0.43）、y240 0.65（参考 0.65）、y264 0.78（参考 0.80）。
- **电机端盖**：试过把左端改成能看到端面的椭圆，但量下来参考的左端轮廓在 x=70 处比顶边低 3–6px（逐行取亮度，6px 一档），
  更符合现在的圆角（r=23，算出来低 6.5px），椭圆（rx≈12）只低 1px。所以保留圆角，圆柱感靠明暗解决。
- **窄屏电路板**：手机上不再整块悬在半空，上沿往上渐隐。
- **README**：补了「其他单页动效」一节，列出全部 6 个页面。
